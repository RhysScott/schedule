### 整体架构

```
┌──────────────┐         ┌──────────────┐
│   App 端     │◄───────►│   云端服务   │◄───────►┌──────────────┐
│ （学生干部用 │         │  （数据存储）│         │  管理后台    │
│              │         │              │         │ （负责人用） │
└──────────────┘         └──────────────┘         └──────────────┘
  日常看课表               统一数据库                数据分析
  接收通知                 用户权限                  任务管理
  简单操作                 AI识别服务                排班决策
```

两端共用一个数据库，数据实时同步。App端产生的数据（课表、签到等），管理后台实时可见。

### App端设计（学生干部日常使用）

#### 定位
轻量、高频、好用。打开就能看课，不用动脑子。

#### 核心页面

**首页 - 今日课表**
- 打开App第一眼看到今天有什么课
- 每节课显示：课程名、教室、上课时间
- 没课的时段灰色标记"空闲"
- 顶部显示"今天有X节课，空闲X个时段"
- 当前时间最近的下一节课高亮提醒

**周视图**
- 经典课程表网格布局，周一到周五（或周日）× 各节次
- 可以点击任意格子查看详情或手动修改
- 支持左右滑动切换周次（如果涉及单双周）

**消息中心**
- 接收管理员派发的任务通知
- 会议/活动通知
- 课表变更提醒

**个人中心**
- 重新导入课表（调课后更新）
- 提醒设置（课前多久提醒）
- 小组件设置

#### 交互原则
- 打开到看到课表不超过2秒
- 核心操作（看课表）不需要登录态以外的任何额外步骤
- 支持桌面小组件，不打开App也能看到下一节课

### 管理后台设计（你日常使用）

#### 定位
功能全面、数据丰富、辅助决策。在电脑浏览器上打开使用。

#### 核心模块

**仪表盘（首页）**
- 团队总人数、本学期课表已导入率
- 今日/本周活动安排概览
- 待处理事项提醒（比如有人课表还没导入）

**全员课表总览**
- 矩阵视图：行是人，列是时间段，单元格显示课程名或"空闲"
- 支持按部门/年级/专业筛选
- 支持按时间段筛选，比如只看"周二下午"所有人的情况
- 底部汇总行：每个时间段的空闲人数统计

**空闲分析**
- **热力图**：用颜色深浅展示每个时段的空闲率，深色=空闲人多，一眼找到黄金时段
- **推荐时段**：你要开会时，输入"需要X人以上"，系统自动推荐符合条件的时段
- **个人对比**：选几个人，对比他们的空闲时段重合度

**任务管理**
- 创建任务 → 选择执行人（可根据空闲情况筛选）→ 设置截止时间
- 任务看板：待办/进行中/已完成，拖拽切换状态
- 任务关联时间段：比如"周三下午布置展板"，系统自动检查执行人该时段是否有课

**排班管理**
- 值班排班表：根据每人空闲时段智能推荐排班方案
- 活动签到统计
- 冲突检测：排班时自动提示"该同学此时段有课"

**人员管理**
- 邀请码生成与管理
- 成员列表：部门、职务、课表导入状态、账号状态
- 一键禁用/启用账号（干部离任时）

**数据导出**
- 导出全员课表矩阵为Excel
- 导出空闲统计报表
- 导出任务完成情况统计
- 导出考勤/签到记录

### 两端数据流转关系

| 操作 | 发起端 | 数据流向 |
|------|--------|----------|
| 导入课表 | App端 | 学生拍照 → AI识别 → 存入云端 → 管理后台实时可见 |
| 查看空闲 | 管理后台 | 汇总所有人课表 → 生成矩阵和统计 |
| 派发任务 | 管理后台 | 创建任务 → 推送到App端消息中心 |
| 签到打卡 | App端 | 学生扫码/点击 → 存入云端 → 后台统计更新 |
| 课表变更 | App端 | 学生重新导入 → 云端更新 → 后台矩阵自动刷新 |

### 权限体系

| 角色 | App端权限 | 管理后台权限 |
|------|-----------|-------------|
| 普通成员（学生干部） | 看自己的课表、接收通知、签到 | 无 |
| 部门部长 | 看自己的课表 + 看本部门成员空闲情况 | 本部门的数据分析 |
| 负责人（你） | 全部功能 | 全部数据 + 人员管理 + 邀请码管理 |

### 技术选型建议

| 层面 | 推荐方案 |
|------|----------|
| App端 | Flutter（一套代码出双端） |
| 管理后台 | Vue3 + Element Plus（成熟的后台UI框架） |
| 后端API | Node.js / Python FastAPI |
| 数据库 | PostgreSQL（结构化数据） + Redis（缓存热点查询） |
| AI识别 | 通义千问VL / GPT-4o 视觉能力 |
| 文件存储 | 阿里云OSS（存课表截图原图） |
| 推送 | 极光推送 / Firebase |
